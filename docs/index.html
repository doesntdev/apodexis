A compiled language for agent-written tools.

Apodexis turns agent-authored source into checked native programs, with deterministic core semantics, bounded execution, and structured validation and repair over MCP.

01 / The idea

A smaller surface.
A more inspectable tool.

Agents already write Python, JavaScript, and shell. Apodexis explores whether a smaller, typed, machine-checkable language can make generated tools easier to validate, repair, bound, and audit.

It is a programming language, not a prompt language, agent planner, or ML framework. It contains no model and needs no API key. Humans can use the same compiler from the command line.

Connect an agent via MCP ↗
  1. 01

    Check before running.

    Explicit signatures, typed values, and structured diagnostics expose mistakes before execution. Canonical source and entrypoint contracts make the program inspectable.

  2. 02

    Repair against compiler facts.

    Machine-readable diagnostics and guarded canonical-source repairs support an explicit verify–repair–verify loop, not arbitrary semantic program synthesis.

  3. 03

    Make limits and authority explicit.

    Run representative JSON inputs under fuel and input/output limits. Host access belongs to an operator-owned policy and trusted broker, never to generated source.

02 / Available now

Native tools.
Explicit boundaries.

Read the implemented contract ↗
01 A native compiler
A standalone C99 frontend and C runtime, using QBE 1.3 to produce Linux x86-64/glibc executables. No interpreter or JIT fallback.
02 Typed, immutable values
Functions, structs, arrays, string-keyed maps, option/result values and matching, conditionals, loops, and local builders. Local updates preserve old aliases.
03 Bounded execution
Checked arithmetic, indexing, and builder capacity. Deterministic fuel accounting, with finite memory, recursion, CPU, input/output, and worker bounds.
04 Structured agent tooling
Local MCP discovery, language resources, diagnostics, guarded repairs, source tests, JSON contracts, execution, and deterministic pseudocode for review.
05 Modules and pure libraries
Explicit imports and exports, sibling-file CLI resolution, and inline MCP bundles. Unicode-scalar string operations, strict conversions, maps, and immutable array and record updates.
06 Deliberately granted effects
Brokered file reads/writes, named environment reads, wall clock, entropy, and exact-URL HTTP GET. Only an operator-owned CLI capability policy grants access; ordinary MCP calls and source tests remain ungranted.
07 Typed JSON documents
Decode strict JSON strings into declared scalar, array, map and record types, including imported records. Data errors return typed results; resource exhaustion remains terminal. See the configuration validator and its test cases.

Know the boundary.

Deterministic describes pure computation—not file, network, clock, or entropy observations. This is experimental software, not an independently audited security boundary or a production-readiness claim.

There is no WASM/browser target, GPU backend, HTTP listener, database adapter, event loop, package registry, or LSP today. Option/result/enum JSON inputs and a stable packaged embedding library are not supported.

Same valid-input work. Different guarantees.

Record differences retain the same scan algorithm; collection results are checked in full. Apodexis keeps checked arithmetic, fuel and immutable snapshots. Baselines use ordinary owned collections and do not emulate its memory quota, capabilities or snapshot contract. JSON libraries and representations differ; these timings do not isolate the cost of any one safety feature.

Toolchains: GCC 15.2 (-O3 for C), QBE 1.3 with the default -O2 C runtime, Rust 1.95 release with overflow checks, Python 3.14.9, Node 24.15.0. One logical CPU, unchanged powersave governor, normal GC. All selected cases and rounds are retained; the small corpus is not independently reproduced.

04 / Future directions

Broader targets.
Simpler delivery.

Goals, not current capabilities. These directions have no promised release dates or compatibility guarantees.

  1. 01

    Native WebAssembly support

    Explore a WebAssembly target alongside the native toolchain. The current implementation has no WASM/WASI or browser target.

  2. 02

    Easier deployment

    A more straightforward path from checked source to a tool someone else can run. Today, the native distribution still requires its documented layout and Linux x86-64/glibc prerequisites.

05 / Build & contribute

Start with the source.

Build locally on Linux x86-64 with glibc. You’ll need a C99 compiler, GNU Make, the platform as/ld, and C library development files. QBE is vendored; the source build fetches no compiler dependencies.

Full setup and first-run instructions ↗
From a source checkoutsh
git clone https://github.com/doesntdev/apodexis.git
cd apodexis
make
make check
make test

Produces bin/apodexis and bin/apx-mcp.
Keep the checkout layout intact and its .build/ writable.
